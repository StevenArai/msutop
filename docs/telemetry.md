# Linux 采集与数据处理

`--live` 在 Linux 上读取真实系统指标；Windows 使用模拟数据（mock）。
采集不需要桌面环境，未获得或不可读的温度、功耗等显示 `--`，不会用模拟值填充。
命令行参数可用 `--help` 查看。

## 指标来源与频率

默认数据更新率为 30Hz，可用 `--fps N` 调整。不同来源按其成本和精度分开采集：

| 数据 | 来源／计算 | 默认频率 |
|---|---|---|
| CPU 总体与各逻辑线程利用率 | `/proc/stat` 的计数差，排除 idle，guest 不重复计算 | 30Hz |
| 内存与 swap | `/proc/meminfo` | 30Hz |
| 磁盘读写速率与队列 | `/proc/diskstats` 的扇区及加权 IO 时间差 | 30Hz |
| 网络速率、包活动与状态 | `/proc/net/dev` 与 `/sys/class/net` | 30Hz |
| 显示的两个进程的 CPU、内存与线程数 | 各进程的 `/proc/<pid>/stat` | 30Hz |
| 全进程排名候选 | 扫描 `/proc` 内的进程 | 1Hz |
| 频率、温度、功耗、容量和协商链路速率 | `/sys`、RAPL 与文件系统容量查询 | 1Hz |

高频文件复用打开的句柄，进程退出或 PID 重用时重新打开。只为显示的两个进程
保存图表历史。`--process-hz N` 调整全进程扫描频率；提高它会增加开销。

网卡默认使用 IPv4 默认路由对应接口；网桥的协商速率可从有载波的物理端口读取。
磁盘依据挂载点设备号解析 device-mapper 的底层设备，避免重复计算；容量显示
挂载文件系统的已用／总量。可显式指定：

```sh
./target/release/msutop --live --headless --interface eth0 --disk sda --mount / --seconds 10
```

Linux 磁盘统计的扇区固定按 512 字节换算。内存 cached 包含 Cached、Buffers 和
SReclaimable，减去 Shmem；used 不包含这些可回收部分。屏幕短缺告警用
`free + cached` 判断可用内存，低于总量 10% 时告警；swap 剩余空间不足 10%
时独立告警。

## 进程选择

按 CPU 占用选择两个主要进程，名称尽量稳定，避免轻微排名变化导致来回切换。
实现位于 [src/selection.rs](../src/selection.rs)：

- 排名分数用 3 秒时间常数的指数移动平均（EMA）平滑。
- 名称至少保留 6 秒。新候选须比当前较弱进程高出 2 个百分点或 15%，取较大值，
  并连续满足 3 次排名采样，才替换该位置。
- 两个已显示进程互换排名时，名称位置保持不变。
- 进程退出时，下次采样直接补位，并重置其历史和平滑值。

显示进程的 CPU 先按约 250ms 的滚动时间窗口计算，减少内核计数精度产生的
零值／尖峰；仍每帧更新，再进行数值平滑。进程选择与显示数值使用独立平滑，
全进程扫描不会因此变成每帧扫描。

## 数值与量程平滑

指数移动平均（EMA）让新值逐渐影响显示，减小抖动；权重按实际经过时间计算，
调整帧率不会改变相同时间长度下的响应。`--no-ema` 关闭真实数值平滑，便于对比。

| 显示数值 | 时间常数 |
|---|---:|
| CPU、各线程、频率、温度、功耗 | 0.65 秒 |
| 磁盘／网络速率、磁盘队列 | 0.55 秒 |
| 显示进程的 CPU | 0.90 秒 |

内存、swap、网卡连接状态和包活动保留原始状态；告警立即判断，不由 EMA 的
缓慢变化触发。断网、设备变化、进程退出或身份替换会重置相应平滑。

网络、磁盘 IO 和进程图表还独立平滑自动量程：目标为历史窗口峰值的 110%，
放大时间常数 0.5 秒，缩小 3 秒。网络上下行各有量程，磁盘读写共用量程，
每个进程的量程随其身份保存。IO 量程下限为 16KiB/s，进程为 8%。

完成的曲线节点固定使用生成时的高度，量程变化不会重新缩放旧曲线。
因此不同时间节点的高度对应各自当时量程，绝对速率以数字为准。
重复渲染或暂停不推动量程更新。连续滚动的绘制方式见 [视觉设计](design.md#更新与连续滚动)。

## 功耗与磁盘温度

核心采集器读取可访问的 sysfs 传感器和 RAPL 能量计数。功耗由微焦耳计数差计算，
处理计数器回绕。可选辅助进程用于读取需要额外权限或工具的指标：

```sh
./target/release/msutop --live --headless --seconds 30 \
  --sensor-helper scripts/linux-sensors.py --rgb565 frames.rgb565
```

需要 Python 3；SMART 查询另需 smartctl 及设备读取权限。辅助进程每秒读 RAPL，
每五秒用 `smartctl -B /dev/null -j -A -n standby,0` 查询磁盘温度，有 2 秒超时，
不唤醒待机盘。它在帧循环外通过管道提供最新值，主程序退出后随管道关闭退出。
`--sensor-sudo` 只使用已有的非交互 sudo 权限运行该辅助进程。

## 采集与发送速度

数据采集和串口发送目前在同一主循环。设备若低于目标帧率，会拖慢实际采集；
程序按当前时间采样，不积压或突发补发过期画面。SDL 预览单独按显示器垂直同步
呈现，数据仍按配置频率采集。实际设备开销见 [性能记录](performance.md)。
